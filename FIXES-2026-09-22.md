# Nirmal Karaoke v22 — Ultra-Low-Latency Audience Playback + LRC + Voice UI

## Latency
- Audience host audio no longer depends on an HTMLMediaElement for the preferred receive path. It uses the LiveKit RemoteAudioTrack's MediaStreamTrack directly in a dedicated interactive AudioContext.
- Receiver jitter targets start at 20 ms, with 35/60/100/160 ms adaptive steps, 240 ms hard cap. `RTCRtpReceiver.jitterBufferTarget` is used when supported; `playoutDelayHint` and LiveKit `setPlayoutDelay()` are compatibility fallbacks.
- Audience health sampling increased to 2 Hz (500 ms), allowing faster recovery without jumping to large buffers.
- Host browser display-audio capture now uses a 5 ms latency hint and no speech-oriented echo/noise/AGC processing; captured audio is marked with `contentHint='music'`.
- Audience video can be shed before audio when the downlink is degraded.
- Audio remains stereo, RED-enabled, DTX-disabled, and high-priority.

## LRC
- Host sends the latest LRC and playback clock to late joiners after `GUEST_HELLO`.
- Host pushes the playback clock every 250 ms and on play/pause/metadata events.
- Audience interpolates between clock packets with requestAnimationFrame and updates active-line progress smoothly.

## Voice presets
- Audience mic/DSP AudioContext is now created separately from the music playback context.
- Preset buttons are disabled until mic is enabled and now have clear active/disabled styling.

## Cache
- Audience/client module query strings bumped to v22.

# v23 incremental latency tuning
- Healthy receiver target reduced from 20 ms to 0 ms with 20/40/70/120 ms adaptive steps and 180 ms cap.
- Uses `estimatedPlayoutTimestamp`, `jitterBufferTargetDelay`, and `jitterBufferMinimumDelay` when available to observe live and target playout behavior instead of relying only on lifetime averages.
- Concealment is now measured from interval deltas instead of lifetime cumulative counters, avoiding stale buffer inflation.
- If actual playout delay remains high while loss/jitter/concealment are healthy, the target is pulled back to zero.
- Audience audio receiver remains direct Web Audio, avoiding HTML media element buffering.
- LRC animation uses a 250 ms host clock with interpolation and updates the active line/progress without seeking remote audio.
